# Apple M4 counts replay paired Rust ablations

Three closed warm-only Rust baseline/candidate experiments retain every source, executable and driver identity before and after collection. Each has 24 original application cells (four circuits × 1/64/1024 attempted shots × Strict/Fused), five rotated/reversed paired process rounds, seven observations of at least 50 ms, and 288 indexed events: 48 validation processes and 240 timing processes. Validation compares native counts with complete structured records and flat measurements at four seeds, plus sixteen subsequent RNG words outside timing. No peer, SOTA or cold-request claim follows from these ablations.

## Experiments

- [recorded-tail](recorded-tail/summary.json): bounded affine counts baseline versus constant-time recorded rejection-tail retirement. MSC d5 one-shot warm speedups are 1.217× Strict and 1.248× Fused; 64/1024-shot gains are about 1–4%, with every MSC d5 paired range above one.
- [compact-first](compact-first/summary.json): recorded-tail retirement baseline versus direct compact sidecar reads during scalar counts fallback. MSC d5 at 64/1024 gains 17–26%; all four paired ranges exceed one. Some other cells show warm throughput decreases of about 1–3%; these observations are retained.
- [compact-confirmation](compact-confirmation/summary.json): an independent repeat after final test-only additions and publication integration, using the same production algorithm. MSC d5 speedups at 64 shots are 1.164× Strict / 1.253× Fused, and at 1024 shots 1.188× / 1.269×, all paired ranges above one. MSC d3 Fused 1024 warm throughput decreases about 1.8% (paired 0.976–0.985); surface d7 one-shot decreases about 1%, with both paired ranges below one. Most surface bulk ranges cross one. The compact-first experiment's d9 Strict 1024 decrease does not repeat; it must not be treated as a resolved general regression or as a guaranteed improvement.

Ratios above are baseline latency / candidate latency, numerically equal to candidate throughput / baseline throughput. A throughput decrease of `1-ratio` differs from a latency increase of `1/ratio-1`. Paired ranges are descriptive, not confidence intervals. The M4 host is shared and unpinned. Each probe explicitly warms plan/sampler/model/cache before the timed loop, so this data excludes first-call preparation and compilation. The separate formal peer campaign retains those phases.

## Source provenance and reproduction

[bindings.json](bindings.json) binds every tracked source/fixture/Cargo input in each original header to an immutable reachable Git commit and every untracked measured probe input to the seven retained files in [probe](probe). The recorded-tail candidate originally had a dirty worktree; its exact source was preserved afterward in commit `5302111ef2d46eb51d5d9f28da46ac1048d4b7fb` under tag `benchmark-source/recorded-rejection-tail-scout-2026-10-08`. This preserves the original test-module spelling and all measured SHA256s. It does not rewrite the measured header or pretend the preservation commit was the original measured HEAD. Compact first source is retained by `benchmark-source/compact-counts-replay-scout-2026-10-08`; final source by `benchmark-source/compact-counts-replay-2026-10-08`.

Original headers, closures, events, summaries and driver bytes are unchanged. Executables are not vendored; their observed before/after SHA256s remain in the evidence. The drivers contain original local checkout paths for provenance. To reproduce, check out the corresponding source commits, copy the retained probe files into the matching ignored `drafts` locations used by that driver, adapt its checkout/output roots, then build both release probes with their retained Cargo lockfiles before running. These path adaptations create a new experiment, not the archived one. Probe Cargo's relative `../../rstim` dependency is preserved exactly as measured and resolves at those original ignored locations.
