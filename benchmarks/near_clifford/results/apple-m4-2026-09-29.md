# Near-Clifford P0/P1 benchmark

## Findings

The most important next optimization targets are the fast-path boundaries. These
figures are from one Apple M4 host, `StdRng`, release mode, one thread, and nine
repetitions per point. The JSON companion retains the full timing series and
circuit text. The benchmark checks all fixtures against individual execution
and checks flat output plus RNG continuation against structured output before
timing.

| Comparison | First prepared flat | Warm prepared flat | Interpretation |
| --- | ---: | ---: | --- |
| Requested rank 10 → 11, 1000 shots | 0.282 → 15.033 ms | 0.101 → 15.003 ms | 10 to 11 independent T axes grows the coefficient vector from 1024 to 2048 entries; the cache loop only accepts at most 1024. The actual rank was not instrumented. |
| 73 → 74 independent random measurements, 1000 shots | 28.556 → 40.486 ms | 0.336 → 13.122 ms | A 64-bit symbolic suffix needs nine versus ten random prefix outcomes. A complete nine-level binary tree takes 1023 nodes; a ten-level tree exceeds the 1024-node cache cap. The observed boundary is consistent with this explanation; cache hits were not instrumented. |
| 20q/8T terminal API, 63 → 64 shots | 0.389 → 0.395 ms | 0.056 → 0.054 ms | `NearCliffordExecutor::sample` itself changes from 1.742 to 0.450 ms because the public batch path starts at 64 shots. Reusing `prepare_sampler()` avoids that discontinuity. |

For the three-round synthetic noisy QEC circuit, 100k shots take about 350 ms
with either warm structured or flat output; a prepared sampler does not remove
its per-shot evolution. The two-qubit mid-circuit feedback case likewise takes
about 79 ms for 100k shots in both layouts. These fixtures show where the
terminal improvements do not yet apply. They are workload probes, not a claim
about logical error rates or all QEC circuits.

The next code investigation should first test a multiword symbolic suffix for
more than 64 random bits, then profile the rank-11 active measurement path.
For callers with 1–63 shots, assess whether the 64-shot batch threshold should
be lowered. Increasing the cache node cap alone would allow exponential
growth in memory and does not address the underlying suffix-width limit.
