# v0.3.0 release and migration

RustQEC v0.3.0 publishes the first eight workspace crates to crates.io and ships
native archives for Ubuntu 24.04 x86_64 and macOS 15 Apple silicon. The existing
v0.2.1 Git tag, GitHub Release, and native archives remain available; the
historical 0.2.1 crates were not uploaded to crates.io.

`rustqec-cli` installs the `rustqec` executable, whose own version is 0.3.0.
These eight packages share the 0.3 series, with independent patch releases
allowed after the initial 0.3.0 publication. The four private workspace packages
retain their own versions and remain unpublished. See the
[package guide](../crates-io.md) for the publication graph and verification steps.

## Migrating from the v0.2.1 source APIs

The 0.3.0 library line makes optional capabilities explicit. Default simulator
and matching consumers can use:

```toml
[dependencies]
rand = "0.8"
rstim = "0.3.0"
rmatching = "0.3.0"
```

Enable only the features used by your application:

| Previous use | v0.3.0 configuration |
| --- | --- |
| Import `rstim::cli` or build the `rstim` binary | `rstim` feature `cli` |
| Generate CSS circuits through `rstim` | `rstim` feature `codegen-css` |
| Use the browser shot viewer | `rstim` feature `shot-viewer` |
| Import `qec_code::cli` or build the `qec-code` binary | `qec-code` feature `cli` |
| Compute exact code distance with HiGHS | `qec-code` feature `distance-ilp-highs` |
| Compute exact code distance with Gurobi | `qec-code` feature `distance-ilp-gurobi` |
| Call a `qec-ilp-core` solver adapter | `highs` or `gurobi` feature |

Reusable simulator operations are available through `rstim::operations`, with
compatibility reexports under `rstim::cli` when that feature is enabled. Solver
model types and validation need no solver feature. Requests without a usable
enabled backend return an explicit backend-unavailable error. HiGHS needs native
C/C++ build tools, CMake, and Clang/libclang; Gurobi requires its installation and
runtime/license configuration. On `qec-ilp-core` and `qec-code`, choosing Gurobi does not enable HiGHS.
`rilpqec` always includes HiGHS; its Gurobi feature is additive. Actual Gurobi
runtime and license validation were not performed for this release.

The viewer is disabled by default and does not require CLI parsing. Its files
remain in the downloaded crate archive so users can opt in later; they are only
embedded in the compiled library when `shot-viewer` is enabled. The bundled WASM
is rebuilt with 0.3.0 so exported shot provenance reports the matching simulator
version.

## Installing the commands

Install the primary application from crates.io:

```sh
cargo install --locked rustqec-cli --version 0.3.0
```

It includes envelope matching and CSS generation, with no browser viewer or
HiGHS dependency. Add `--features ilp` for exact envelope MLE.

For the complete Stim-style compatibility command:

```sh
cargo install --locked rstim --version 0.3.0 --bin rstim --features cli,codegen-css,shot-viewer
```

A smaller compatibility CLI can enable only `cli`. Installing a dependency
library does not install its executables. Official native archives include ILP
in `rustqec` and CLI, CSS generation, and the full shot viewer in `rstim`; use
`rustqec capabilities --format json` to inspect the actual binary.

## Repository benchmark and research users

`rmatching` no longer has a `bench` feature or bundled benchmark executables.
Build them from a repository checkout using the private tools package:

```sh
cargo build --release -p rmatching-bench-tools --bin rmatching_microbench
```

`rstim` benchmark workers use its separate `benchmark-tools` feature. `rsinter`
defaults to its core harness; select `rbposd-runner`, `rmatching-runner`,
`ilp-runner`, or `plotting`, or use `full` for the complete research environment.
`make test` enables the standard workspace test feature set explicitly.

## Support scope

Rust 1.88 remains the MSRV. Tested native environments are Ubuntu 24.04 x86_64
and macOS 15 Apple silicon. This is a pre-1.0 release: registry publication
does not expand the numerical acceptance evidence or imply universal decoder
support. Envelope decoding remains beta. Matching requires graphlike DEM
components, error probabilities `0 <= p < 1`, and at most 64 observables.
See the [support contract](https://nzy1997.github.io/rust-qec/support/) for the
supported inputs and limitations; numerical acceptance work continues separately.

## Added decoder packages

`rbposd`, `rilpqec`, and `rsinter` now join the first batch. Their archives ship
self-contained tests and examples. Repository benchmark catalog checks run
separately in CI. `rbposd` documents probability bounds, LSD orders 0/1, OSD
search variants, and low-level matrix preconditions.

`rilpqec` rejects impossible deterministic syndromes instead of returning a
success-looking prediction. Batch-size overflow and output allocation failures
return explicit errors through both direct and compiled APIs. Its README shows
reusing the compiled decoder, packed-byte layout, and solver prerequisites.

Install the recommended replay CLI with
`cargo install --locked rsinter --version 0.3.0 --features rbposd-runner,rmatching-runner`.
Add `plotting` or `ilp-runner` as needed; the slim defaults remain unchanged.
