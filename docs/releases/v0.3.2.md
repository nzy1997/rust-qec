# v0.3.2 release: scoped Envelope MLE Supported

RustQEC v0.3.2 publishes the first **Supported** `envelope-mle` promise. The
promise is deliberately finite: exactly four measured Mid-SWAP workload
points, with no interpolation to other loss rates, batch sizes, distances,
round counts, or circuit families. `envelope-matching` keeps its independent
Supported promise from v0.3.1; v0.3.0 and v0.3.1 remain unchanged.

## Package versions

| Package | Version | Notes |
| --- | --- | --- |
| `rustqec-cli` | 0.3.2 | Adds the version-bound MLE Supported publication |
| `qec-ilp-core`, `qec-code`, `rstim`, `rmatching`, `rbposd`, `rilpqec`, `rsinter` | 0.3.0 | Unchanged; not republished |

## The MLE Supported promise

`envelope-mle` is Supported only for flat loss-visible Mid-SWAP rotated
surface-code memory-Z circuits that satisfy the executable circuit contract
and match one of these exact workload points:

| Distance | Rounds | Loss rate | Batch sizes |
| --- | --- | --- | --- |
| 3 | 2 | 0.002 | 1,024 and 16,384 |
| 3 | 1 | 0.01 | 1,024 and 16,384 |

The official Linux x86_64 and macOS arm64 archives include the required ILP
solver. Source builds must enable `--features ilp`; without it, MLE is absent
from `rustqec capabilities --format json`. The `--shot-timeout-ms` option
bounds each ILP solve phase, not compilation or total batch time. A timeout
returns `decode_timeout`, writes diagnostic statistics, and publishes no
predictions.

Every unlisted point is outside the Supported promise. In particular,
conventional Stim-annotated circuits are excluded from the MLE domain, and
the pinned conventional fixture must reject as `unsupported_circuit` before
creating predictions or statistics. A retained d=5/r=15 acceptance fixture is
a regression witness only; it does not widen the promise.

The exact domain and required correctness, resource, failure-semantics, and
installed-platform evidence are frozen in
[`docs/envelope-mle-scope.json`](../envelope-mle-scope.json).

## Publication evidence

Both official native archives are built from the tagged source and tested
after installation. The release publishes
`envelope-support-evidence-v0.3.2.tar.gz` and its SHA-256 sidecar alongside the
archives. The bundle binds the release tag, source commit, support matrix, MLE
scope plan, correctness and resource reports, and both archive identities.

After downloading every v0.3.2 asset into one directory, verify both decoder
claims offline:

```sh
python3 tools/check_envelope_publication.py \
  --release-dir <download-dir> \
  --expect-decoder envelope-matching \
  --expect-decoder envelope-mle
```

The command ends with `PASS envelope published support` only when the two
distinct scopes and both native archive identities reconcile with the
version-bound evidence. A previous Matching-only release fails when MLE is
required.

## Compatibility

This release does not broaden the accepted circuit language or change the
stable prediction, statistics, and structured-error semantics. The frozen
surface and evolution rules remain defined by
[`docs/envelope-compatibility-policy.md`](../envelope-compatibility-policy.md).
