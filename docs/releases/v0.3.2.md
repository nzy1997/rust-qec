# v0.3.2 release candidate: Hardened Envelope matching promotion

RustQEC v0.3.2 supersedes the incomplete v0.3.1 staging release. It is the
first candidate that can promote `envelope-matching` from Beta to
**Supported** within its verified Mid-SWAP scope using the hardened
post-publication verifier. The promotion becomes binding only after all release
assets are published and the digest-bound verification marker exists.
`envelope-mle` remains Beta.

## Package versions

| Package | Version | Notes |
| --- | --- | --- |
| `rustqec-cli` | 0.3.2 | The only workspace package published for this patch |
| `qec-ilp-core`, `qec-code`, `rstim`, `rmatching`, `rbposd`, `rilpqec`, `rsinter` | 0.3.0 | Unchanged; not republished |

The repository tag records a tested snapshot of the 0.3 series. Every public
crate shares the 0.3 major/minor line, none is ahead of the tag, and
`rustqec-cli` matches the tag version, as required by
[`tools/release_version_policy.json`](../../tools/release_version_policy.json).

## Supported scope

After publication verification, `envelope-matching` is Supported for flat
loss-visible Mid-SWAP rotated surface-code memory-Z circuits within the
executable contract in [`docs/envelope-support.json`](../envelope-support.json)
and the measured operating envelope in the retained
[resource report](../../benchmarks/atom_loss/readiness/resources/report.md).
Finite tested sizes and loss points are witnesses, not a universal circuit,
size, loss-rate, or latency guarantee. The CLI compatibility surface is frozen
by [`docs/envelope-compatibility-policy.md`](../envelope-compatibility-policy.md).

## Hardened publication proof

The release-readiness gate binds the exact matrix, policy, support,
correctness, resource, and installed-artifact reports it evaluates by SHA-256.
The publication verifier repeats the same completeness checks and rejects a
bundle whose correctness detail is missing or whose bound inputs differ, even
when outer package checksums have been recomputed.

The release must publish these version-bound assets:

- `envelope-support-evidence-v0.3.2.tar.gz`
- `envelope-support-evidence-v0.3.2.tar.gz.sha256`
- native archives and checksums for both supported targets
- `envelope-support-verification-v0.3.2.json`, uploaded last

Download all assets into one directory and verify them with:

```sh
python3 tools/check_envelope_publication.py \
  --release-dir <download-dir> \
  --expect-decoder envelope-matching
```

The command must end with `PASS envelope published support`. The website stays
at Beta unless the GitHub Release is final and its asset metadata, digests,
source commit, supported decoder list, evidence bundle, checksum, and
verification marker all reconcile with the support matrix.

## v0.3.1 disposition

The v0.3.1 tag and assets remain immutable for audit history. Its GitHub
Release is marked prerelease, its retained evidence predates the hardened
binding check, no valid verification marker exists, and no v0.3.1 CLI crate was
published. It therefore establishes no Supported Envelope matching claim.
