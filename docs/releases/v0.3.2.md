# v0.3.2 staged candidate: publication metadata inconsistent

The v0.3.2 GitHub Release contains both native archives, an envelope evidence
bundle, and a verification marker. Its evidence bundle records Matching's
`published_support.release` as v0.3.1, even though v0.3.1 never completed the
hardened publication verification. The latest verifier rejects that bundle:

```text
envelope-matching published_support release v0.3.1 does not match its immutable first Supported release v0.3.3
```

Consequently, v0.3.2 is retained as a historical candidate, not the first
verified Supported publication. The tag and all assets remain unchanged for
audit; `rustqec-cli 0.3.2` was not published to crates.io. v0.3.3 is the
corrected release candidate.

The v0.3.2 bundle still contains valuable correctness, resource, and installed
archive results for the two decoders. Its MLE evidence applies only to the
four Mid-SWAP points in the [scope plan](../envelope-mle-scope.json). These
measurements do not repair the contradictory Matching publication record.

Reproduce with all v0.3.2 assets downloaded into one directory:

```sh
python3 tools/check_envelope_publication.py \
  --release-dir <download-dir> \
  --expect-decoder envelope-matching \
  --expect-decoder envelope-mle
```
