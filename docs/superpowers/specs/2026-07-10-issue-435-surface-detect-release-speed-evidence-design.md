# Issue 435 Surface Detect Release Speed Evidence Design

Issue: #435

## Context

Issue #433 is merged into `master` and provides
`benchmarks.rstim_vs_stim_simulator.run_speed_suite`, which builds the selected
`rstim` profile once and emits a scoped `summary.json`, `report.md`,
`environment.json`, and temporary raw timing stream for exactly the requested
case labels.

Issue #434 is also merged and provides
`tools/check_rstim_vs_stim_release_speed_case.py`, plus checked release evidence
for `rep-sample-d13-r13`. Issue #435 asks for the same checked-publication
shape, but for the existing detector workload `surface-detect-d13-r13`.

## Approaches Considered

1. Reuse the #433 suite runner for a one-case release bundle under
   `benchmarks/rstim_vs_stim_simulator/results/release-surface-detect/`, reuse
   the #434 checker, and extend its workload mismatch wording/test coverage.
   This is selected because it follows the dependency chain, keeps evidence
   isolated from existing release directories, and directly validates that the
   detector workload is not mislabeled as a sample workload.

2. Hand-copy a subset of `results/full/` or another existing speed result into a
   new checked directory. This is rejected because it would not prove the
   current release-profile runner and checker can reproduce the detector case.

3. Add a detector-specific checker. This is rejected because the generic checker
   already validates the important release-speed evidence contract; duplicating
   it would increase maintenance cost without adding useful coverage.

## Design

The checked detector evidence lives in:

```text
benchmarks/rstim_vs_stim_simulator/results/release-surface-detect/
```

with exactly these published files:

- `summary.json`, generated by
  `python3 -m benchmarks.rstim_vs_stim_simulator.run_speed_suite --profile release --cases surface-detect-d13-r13 --warmup-rounds 0 --measure-rounds 1`;
- `report.md`, generated from that summary by the existing `rstim perf report`
  path;
- `environment.json`, generated by the suite runner and then marked with
  `evidence_kind = "surface detect release speed evidence"`,
  `published_artifact = true`, and `source_issue = 435`.

The summary must contain exactly one case with `case_label =
"surface-detect-d13-r13"` and `workload = "detect"`. The three required
variants are `stim-cli`, `rstim-interpreted`, and `rstim-compiled`; each must
appear in the case's `variants` list with `status = "completed"`, and each must
also appear in `present_variants`.

The checker remains threshold-free. For detect workloads, the evidence can be
accepted from wall-time fields alone; shots-per-second may be present but is not
part of the validation contract.

## Checker

Reuse `tools/check_rstim_vs_stim_release_speed_case.py` with this command:

```sh
python3 tools/check_rstim_vs_stim_release_speed_case.py \
  --results-dir benchmarks/rstim_vs_stim_simulator/results/release-surface-detect \
  --case surface-detect-d13-r13 \
  --workload detect \
  --required-variants stim-cli,rstim-interpreted,rstim-compiled
```

On success it prints:

```text
PASS release speed case surface-detect-d13-r13
```

The checker already validates the artifact set, case uniqueness, required
variant completion, release profile, environment metadata, and report scope.
For this issue, workload failures should include:

```text
workload mismatch for surface-detect-d13-r13
```

so a sample-labeled detector fixture is rejected with the exact negative-control
signal requested by the issue.

## Tests

Extend `tools/test_check_rstim_vs_stim_release_speed_case.py` with a detector
fixture whose `case_label` is `surface-detect-d13-r13` and whose workload is
incorrectly set to `sample`. Running the checker with `--workload detect` must
exit nonzero and write `workload mismatch for surface-detect-d13-r13` to
stderr.

Run the issue-required checker command against the checked detector evidence,
the checker unit tests, and `cargo test`.

## Scope Limits

Do not add any hard Stim ratio gate. Do not change detector semantics. Do not
modify existing checked evidence under `benchmarks/rstim_vs_stim_simulator/results/full/`,
`benchmarks/rstim_vs_stim_simulator/results/release/`, or
`benchmarks/rstim_vs_stim_simulator/results/release-repetition-sample/`.
