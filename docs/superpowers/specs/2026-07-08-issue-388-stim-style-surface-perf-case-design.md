# Issue 388 Stim-style Surface Perf Case Design

## Objective

Add the report-only perf registry case
`stim-style-surface-sample-d11-r100-b1024` for Stim's upstream
`FrameSimulator_surface_code_rotated_memory_z_d11_r100_batch1024` sampling
workload. The case must use the checked Stim-generated fixture from issue #385,
not a circuit regenerated by `rstim`.

## Selected Approach

Extend the existing perf case model with a checked fixture source variant and
attach the fixture's explicit noise contract to that source. The new source
points at:

```text
benchmarks/rstim_vs_stim_simulator/fixtures/stim_surface_code_rotated_memory_z_d11_r100.stim
```

The fixture source records `case_id = "stim_surface_d11_r100"` and the
root-relative canonical input path used by the #385 manifest. The runner reads
that checked file from the repository root at measurement time.

This is the recommended approach over two alternatives:

- A manifest loader would couple the Rust perf registry to TOML parsing for one
  case and add more surface area than the issue needs.
- A regenerated `rstim` surface-code source would directly violate the issue's
  fixture-first scope and would blur generator parity with simulator timing.

## Perf Contract

`benchmark_cases()` will include one additional case:

- `label = "stim-style-surface-sample-d11-r100-b1024"`
- `workload = PerfWorkload::Sample`
- `shots = Some(1024)`
- `tier = PerfCaseTier::ReportOnly`
- `source = PerfCircuitSource::Fixture { ... }`
- `case_id = "stim_surface_d11_r100"`
- `canonical_input_path =
  "benchmarks/rstim_vs_stim_simulator/fixtures/stim_surface_code_rotated_memory_z_d11_r100.stim"`
- nonzero Stim-style noise channels:
  - `after_clifford_depolarization = 0.001`
  - `after_reset_flip_probability = 0.001`
  - `before_measure_flip_probability = 0.001`
- explicit zero channel:
  - `before_round_data_depolarization = 0.0`

The case remains report-only and does not add a hard Stim-vs-`rstim` speed
threshold.

## Variant Contract

The case expects the same sampling variants as compiled-compatible sample
workloads:

- `stim-cli`
- `rstim-interpreted`
- `rstim-compiled`

The existing same-run compiled-vs-interpreted comparison remains a routing
check for `rstim` backends. This design does not make a cross-tool speed claim
and does not compare absolute Stim and `rstim` times against a threshold.

## Implementation Notes

Add a small `PerfNoiseMetadata` struct rather than reusing `NoiseParams`. That
keeps the fixture metadata explicit and makes the uniform-noise pitfall visible:
`NoiseParams::uniform(0.001)` would set
`before_round_data_depolarization = 0.001`, which is invalid for this
Stim-style fixture contract.

Update the perf runner's source loader to read checked fixture files using the
crate's compile-time manifest directory to find the workspace root. Existing
inline and generator sources keep their current behavior.

## Tests

Add a focused `rstim/tests/perf_harness.rs` test named
`benchmark_cases_include_stim_style_surface_sample_contract`. It verifies:

- label, workload, shots, and report-only tier;
- fixture source case ID and canonical path;
- all explicit noise fields, including zero
  `before_round_data_depolarization`;
- the case does not use a generator source;
- expected variants are `stim-cli`, `rstim-interpreted`, and
  `rstim-compiled`.

The negative-control behavior is represented by assertions that the fixture
contract differs from `NoiseParams::uniform(0.001)` and that the source is not a
regenerated `PerfCircuitSource::Generator`.

Run the issue's exact verification command and then the repository's
`cargo test` gate.

## Scope Limits

This change does not optimize sampler performance, add generator-parity checks,
or require the new report-only case to beat Stim. It only adds the perf registry
contract and the source loader needed to consume the checked #385 fixture.
