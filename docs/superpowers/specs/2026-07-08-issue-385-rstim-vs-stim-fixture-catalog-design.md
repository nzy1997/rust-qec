# Issue 385 rstim-vs-Stim Fixture Catalog Design

## Objective

Add a source-grounded fixture catalog for future `rstim` vs Stim simulator
sampling comparisons. The catalog pins checked Stim-generated circuit text,
workload metadata, noise contracts, shot counts, and provenance without
optimizing or timing either simulator.

## Selected Approach

Use a focused Python benchmark package under
`benchmarks/rstim_vs_stim_simulator/`, matching the repository's existing
benchmark style. The package owns TOML manifests, checked `.stim` fixtures,
and a validator entry point:

```sh
python3 -m benchmarks.rstim_vs_stim_simulator.validate_cases <manifest>
```

The smoke manifest contains three validated fixture entries so the issue's
required command prints `PASS 3 fixture cases`. Two entries are small smoke
workloads, and one entry documents the canonical full Stim-style workload. The
full manifest contains the executable full workload entry for later benchmark
runner work.

## Manifest Schema

Each manifest is TOML with:

- `manifest_version = 1`
- `suite = "rstim_vs_stim_simulator"`
- `generated_outputs_root = "benchmarks/out/rstim_vs_stim_simulator"`
- `[[cases]]` entries with flat fields for stable review diffs.

Each case records:

- `case_id`
- `tier`, one of `smoke`, `full`, or `documentation-only`
- `source = "stim"`
- `workload`, `code`, `task`, `distance`, and `rounds`
- `canonical_input_path`
- `generation_command`
- explicit noise fields:
  - `after_clifford_depolarization`
  - `after_reset_flip_probability`
  - `before_measure_flip_probability`
  - `before_round_data_depolarization`
- `shots`
- `expected_qubits`
- `expected_measurements`
- `expected_detectors`
- `expected_observables`
- `stim_version`
- `provenance`

The schema intentionally stays flat. It is easier to inspect in GitHub review
and avoids TOML array-of-table nesting surprises.

## Fixtures

Store checked circuit inputs under
`benchmarks/rstim_vs_stim_simulator/fixtures/`.

The canonical full fixture is generated by Stim, not by `rstim`, using:

```sh
stim gen --code surface_code --task rotated_memory_z --distance 11 --rounds 100 --after_clifford_depolarization 0.001 --after_reset_flip_probability 0.001 --before_measure_flip_probability 0.001 --before_round_data_depolarization 0 --out benchmarks/rstim_vs_stim_simulator/fixtures/stim_surface_code_rotated_memory_z_d11_r100.stim
```

The validator enforces the full case's noise contract exactly:

- `after_clifford_depolarization = 0.001`
- `after_reset_flip_probability = 0.001`
- `before_measure_flip_probability = 0.001`
- `before_round_data_depolarization = 0`

This explicitly avoids `NoiseParams::uniform(0.001)`, whose
`before_round_data_depolarization` behavior is out of scope for this Stim-style
case.

## Validation

`validate_cases.py` loads TOML with `tomllib`, validates required fields and
types, rejects duplicate case IDs, verifies canonical input paths stay inside
the benchmark package, parses each checked `.stim` file with the installed
Stim Python package, and compares actual counts against expected metadata.

For the canonical full case, the validator emits the exact actionable error
substring required by the issue when the uniform-noise pitfall is present:

```text
before_round_data_depolarization must be 0 for stim_surface_d11_r100
```

The validator prints `PASS N fixture cases` on success.

## Tests

Add Python unit tests under
`benchmarks/rstim_vs_stim_simulator/tests/` for:

- the smoke manifest CLI success output;
- the full manifest CLI success output;
- the negative control
  `benchmarks/rstim_vs_stim_simulator/tests/fixtures/bad_uniform_noise.toml`;
- required smoke case IDs and the canonical full case metadata.

Run the issue's explicit commands plus `cargo test` for repository verification.

## Scope Limits

This change does not add a simulator runner, speed benchmark, correctness
comparison, or `rstim` generator parity check. It only builds the shared fixture
catalog and validation surface that later issues can consume.
