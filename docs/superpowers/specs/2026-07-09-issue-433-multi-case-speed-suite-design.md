# Issue 433 Multi-Case Speed Suite Design

## Objective

Add a Python module entrypoint for multi-case `rstim`-vs-Stim release speed
examples:

```text
python3 -m benchmarks.rstim_vs_stim_simulator.run_speed_suite \
  --profile release \
  --cases rep-sample-d13-r13,surface-detect-d13-r13,stim-style-surface-sample-d11-r100-b1024 \
  --warmup-rounds 0 \
  --measure-rounds 1 \
  --out-dir /tmp/rstim-speed-suite
```

The runner must build the selected `rstim` profile once, run exactly the
requested perf cases, and write one coherent artifact bundle:
`raw.jsonl`, `summary.json`, `report.md`, and `environment.json`.

## Context

`benchmarks.rstim_vs_stim_simulator.run_speed_case` already provides the
single-case Python wrapper. It owns build-profile selection, tool probing, and
environment metadata. The Rust `rstim perf` CLI owns case definitions, variant
selection, timing, summary calculation, and Markdown rendering.

The existing Rust summarizer can summarize one selected case or the whole
registry. Whole-registry summarization is not appropriate for this issue
because the summary artifact would include missing-data issues for cases that
were intentionally not requested.

## Selected Approach

Create `benchmarks/rstim_vs_stim_simulator/run_speed_suite.py` as a thin suite
orchestrator that reuses `run_speed_case.py` helpers and the Rust perf CLI.
The suite runner will:

- parse `--profile`, comma-separated `--cases`, `--warmup-rounds`,
  `--measure-rounds`, and `--out-dir`;
- reject an empty parsed case list with `no benchmark cases requested`;
- build `target/debug/rstim` or `target/release/rstim` once by calling the
  existing `build_rstim`;
- validate each requested label through the built `rstim` CLI case registry;
- invoke `rstim perf run --case <label>` for each requested label and append
  those raw records to one `raw.jsonl`;
- invoke `rstim perf summarize --case <label>` for each requested label using
  the suite raw JSONL, then merge only those selected case summaries into one
  `summary.json`;
- invoke `rstim perf report` once on the merged summary;
- write one `environment.json` with the requested case list, profile, command
  line, selected binary path, Rust/Cargo versions, and Stim probe metadata.

This is preferred over looping over `run_speed_case.py` because it avoids one
Cargo build and one environment bundle per case. It is preferred over running
the full Rust perf suite because both raw and summary artifacts contain only
the requested labels.

## Artifact Semantics

`raw.jsonl` contains only records emitted by selected `perf run --case`
invocations. The suite runner never calls unfiltered `rstim perf run`.

`summary.json` has this top-level shape:

```json
{
  "cases": [],
  "issues": []
}
```

Each requested label contributes the `cases` and `issues` from its own
`rstim perf summarize --case <label>` result. The runner preserves the
requested case order and does not add missing-data issues for unrequested
registry cases.

`report.md` is generated by the existing `rstim perf report` command from the
merged `summary.json`, so report formatting remains owned by Rust.

`environment.json` keeps the existing single-case probe fields and adds:

- `case_labels`: requested labels in order;
- `case_count`: number of requested labels;
- `command_line`: exact Python argv used by `main`.

## Error Handling

`--cases ""` and comma lists containing only blanks exit nonzero before
building or creating evidence files and print `no benchmark cases requested`.

Unknown labels are validated through the built `rstim` CLI, so failures contain
`unknown benchmark case` from the Rust registry. The suite fails before timing
any case if any requested label is unknown.

Duplicate labels are rejected with `duplicate benchmark case` to avoid
ambiguous raw measurement slots.

Successful perf subcommands must create their expected artifacts. If a raw,
per-case summary, merged summary, report, or environment file is missing, the
runner fails with a clear missing-artifact error.

## Tests

Add Python unit coverage in
`benchmarks/rstim_vs_stim_simulator/tests/test_run_speed_suite.py`:

- empty `--cases` returns nonzero and prints `no benchmark cases requested`;
- unknown labels surface `unknown benchmark case`;
- the suite builds once for multiple labels;
- each requested case gets one `perf run --case` call;
- per-case summaries are merged into a single `summary.json` containing exactly
  the requested labels in order;
- `report.md` is generated once from the merged summary;
- `environment.json` records `case_labels`, `profile`, command line, binary
  path, Rust/Cargo versions, and Stim probe status.

Run the issue verification command, focused Python unit tests, negative
controls for empty and unknown cases, and the repository `cargo test` gate.

## Scope Limits

Do not publish checked benchmark evidence. Do not add performance thresholds
against Stim. Do not duplicate timing, variant selection, summary statistics,
or Markdown rendering in Python.
