# Issue 562 Coprime Bivariate-Bicycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a typed coprime bivariate-bicycle CSS constructor that lowers to the #558 generalized-bicycle constructor and matches the `[[30,4,6]]` fixture.

**Architecture:** Add a small `coprime_bb` module that owns period/support validation, the `pi = xy` index-map helper, and lowering to `GeneralizedBicycleSpec`. Extend `family_contract.rs` so Rust API and structured JSON CLI requests construct through the shared result/provenance path.

**Tech Stack:** Rust 2024, serde, existing `qec-code` sparse GF(2), existing generalized-bicycle constructor, existing `code css construct --spec` CLI.

## Global Constraints

- Preserve #558 block convention exactly: `H_X = [A | B]`, `H_Z = [B^T | A^T]`.
- `pi^t` maps to `(t mod l, t mod m)` for `pi = xy` and `0 <= t < l * m`.
- Reject zero periods, non-coprime periods, empty support lists, duplicate canonical exponents, and exponents outside `0..l*m`.
- Store the complete `l=3,m=5` fixture under `qec-code/tests/fixtures/coprime_bb/`.
- Required exact checks:
  `cargo test -p qec-code --test coprime_bb coprime_bb_3_5_matches_30_4_6_fixture -- --exact`
  and
  `cargo test -p qec-code --test coprime_bb coprime_bb_rejects_non_coprime_periods -- --exact`.
- Run final `cargo test` before PR creation.

- [ ] **Step 1: Implement typed spec and normalization**

Add the module with:

Validation should compute `cyclic_order = l.checked_mul(m)` after nonzero and
coprime checks, then reuse the same exponent normalization style as #558.

- [ ] **Step 2: Implement `pi` map and lowering**

Add:

```rust
pub fn coprime_pi_power_index(l: usize, m: usize, exponent: usize) -> Result<(usize, usize)> {
    let normalized = normalize_periods(l, m)?;
    if exponent >= normalized.cyclic_order {
        return Err(invalid(format!(
            "pi exponent {exponent} is out of range for cyclic order {}",
            normalized.cyclic_order
        )));
    }
    Ok((exponent % l, exponent % m))
}
```

`coprime_bb_sparse_checks` should normalize the coprime spec, build a
`GeneralizedBicycleSpec` with `order = cyclic_order`, and return the generalized
checks plus normalized coprime metadata.
