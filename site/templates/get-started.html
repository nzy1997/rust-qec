    1. Install with Cargo

    Requires Rust and Cargo. Install Rust or use the native package.

    cargo install --locked rustqec-cli

    Cargo installs the latest stable rustqec-cli package and places rustqec in ~/.cargo/bin by default. Open a new terminal after installing Rust so this directory is on PATH. For a reproducible build, use the exact package version shown in Version and support boundaries.

    rustqec --version
    rustqec {{ docs_version.packages.rustqec_cli.version }}

    The version command completed successfully. Continue to create your circuit; use rustqec --help whenever you need to discover the available subcommands.

    Alternative: install native binaries without Rust

    Validated runtime environments: Ubuntu 24.04 x86_64 and macOS 15 Apple silicon. Other platforms are outside the tested support matrix. Each archive contains rustqec and rstim.

    Linux x86_64 archivemacOS arm64 archiveChecksums and release manifest

    The installer downloads the prebuilt rustqec and rstim binaries, checks their pinned SHA-256, and installs them into ~/.local/bin. This path does not require Rust.

    curl -fsSL https://nzy1997.github.io/rust-qec/install.sh | sh

    If ~/.local/bin is not already in your PATH, run this once in the terminal you will use for the examples:

    export PATH="$HOME/.local/bin:$PATH"

    The installer prints the installation location and any required PATH setup. It does not use sudo or edit your shell configuration. Use an empty working directory for the circuit files in step 2.

    Inspect the installerDownload an archive manually
    Manual download and checksum verification

    Use an empty working directory. This alternative downloads and checks the archive manually, then adds the extracted binaries to this terminal's PATH.

    set -eu
case "$(uname -s)-$(uname -m)" in
  Linux-x86_64) target=x86_64-unknown-linux-gnu ;;
  Darwin-arm64) target=aarch64-apple-darwin ;;
  *) echo "No validated native archive for this platform" >&2; exit 1 ;;
esac
base=https://github.com/nzy1997/rust-qec/releases/download/v{{ docs_version.native_release }}
archive="rustqec-v{{ docs_version.native_release }}-${target}.tar.gz"
curl -fLO "$base/$archive" -O "$base/SHA256SUMS" -O "$base/release-manifest.json"
awk -v archive="$archive" '$2 == archive { n++; record=$0 } END { if(n != 1) exit 1; print record }' SHA256SUMS > "$archive.sha256"
if command -v sha256sum >/dev/null; then
  sha256sum -c "$archive.sha256"
else
  shasum -a 256 -c "$archive.sha256"
fi
tar -xzf "$archive"
export PATH="$(pwd)/${archive%.tar.gz}/bin:$PATH"

    Success: the checksum command reports OK. If a checksum fails, stop and download a fresh archive.

    rustqec --version

    Success: the command prints the installed version. The example below uses rstim for SVG rendering and rustqec for circuit inspection.

    2. Create and inspect a circuit

    {% include "partials/example-circuit.html" %}

    Render the circuit as an SVG with the companion rstim CLI:

    rstim render_svg --in circuit.stim --out circuit.svg

    Native archives include both rustqec and rstim. If you installed only rustqec-cli with Cargo, install the renderer separately with cargo install --locked rstim --bin rstim --features cli,codegen-css.

    rustqec circuit stats --in circuit.stim
    instruction_count: 5
repeat_blocks: 0
max_repeat_depth: 0
num_qubits: 1
num_measurements: 1
num_detectors: 1
num_observables: 1
num_ticks: 0
num_sweep_bits: 0

    The circuit contains one qubit, one measurement, one detector, and one logical observable.

    3. Sample and verify a detector event

    rustqec circuit detect \
  --in circuit.stim \
  --shots 1 \
  --out-format dets \
  --append-observables \
  --out events.dets
rustqec circuit dem --in circuit.stim --out model.dem
    shot D0 L0
    error(1) D0 L0

    The X error has probability 1. The detector stream therefore contains D0 and logical observable L0; the DEM records the same probability-1 event. This small example verifies installation and the command path; it is not a numerical-performance benchmark.

    Before decoding: this probability-1 model is intentionally deterministic, while rmatching accepts error probabilities in the range 0 ≤ p < 1. The decoding tutorial therefore creates a separate probability-0.1 model and explains the change before it runs the decoder.

    Add optional CLI features

    cargo install --locked rustqec-cli --features ilp

    The default install already includes circuit and dataset tools plus envelope matching. Use this optional reinstall for exact envelope MLE, after installing the native solver build prerequisites. Official native archives include ILP and the viewer. For automated capability checks, rustqec capabilities --format json provides machine-readable metadata.

    For the complete Stim-style compatibility command, install rstim separately with cargo install --locked rstim --bin rstim --features cli,codegen-css,shot-viewer. Internal benchmark workers are not installed by default. rilpqec always includes HiGHS; enabling its Gurobi feature adds a separately configured backend. See the crate publishing and feature guide.

    Build the development version from source

    Guides that require a repository checkout use the source below. To reproduce the coordinated RustQEC {{ docs_version.release_line }} release, use the v{{ docs_version.native_release }} source instructions instead. Current development builds are tested with Rust 1.88.0 (MSRV) and stable on the two native targets above. Install Rust and the platform's native build dependencies before building.

    Ubuntu 24.04 build prerequisites
    sudo apt-get update
sudo apt-get install -y build-essential clang cmake libclang-dev pkg-config libfontconfig1-dev python3-venv
    macOS 15 build prerequisites
    xcode-select --install
brew install cmake fontconfig pkg-config python

    Homebrew must already be installed.

    git clone --branch master --depth 1 https://github.com/nzy1997/rust-qec.git
cd rust-qec
cargo build --locked --workspace --features rstim/cli,rstim/codegen-css,rstim/shot-viewer,rustqec-cli/ilp
export PATH="$(pwd)/target/debug:$PATH"
    Frozen source: v{{ docs_version.native_release }}

    Use this separate checkout for release reproduction. Development-only guides require master above.

    git clone --branch v{{ docs_version.native_release }} --depth 1 https://github.com/nzy1997/rust-qec.git rust-qec-v{{ docs_version.native_release }}
cd rust-qec-v{{ docs_version.native_release }}
cargo build --locked --workspace --features rstim/cli,rstim/codegen-css,rstim/shot-viewer,rustqec-cli/ilp
export PATH="$(pwd)/target/debug:$PATH"

    You can now run the same circuit example. Benchmark workflows may additionally need Python dependencies; use the setup guide linked from each workflow. The development build guide describes test prerequisites.

    Version and support boundaries

    This is RustQEC {{ docs_version.release_line }} · {{ docs_version.channel | title }} documentation. RustQEC {{ docs_version.release_line }} names the coordinated repository release line; each published crate can receive its own compatible patch update. A package requirement is shown only when a guide depends on that package.

    PackageVersion in this sourceUse
    rustqec-cli{{ docs_version.packages.rustqec_cli.version }}Unified rustqec command
    rstim{{ docs_version.packages.rstim.version }}Simulator, DEM, and diagram CLI/API
    rmatching{{ docs_version.packages.rmatching.version }}Graphlike MWPM library
    qec-code{{ docs_version.packages.qec_code.version }}CSS construction and distance CLI/API

    The primary Cargo commands install the latest stable package. To reproduce this checkout exactly, use cargo install --locked rustqec-cli --version {{ docs_version.packages.rustqec_cli.version }}. For the newest compatible patch in the {{ docs_version.release_line }} line, use --version '~{{ docs_version.release_line }}'. Native archives remain tied to the coordinated v{{ docs_version.native_release }} repository release.

    Feature maturity belongs to the package that exposes the feature. Envelope matching and Envelope MLE have separate, version-bound support evidence and limited scopes; a decoder remains Beta until its release evidence passes publication verification. This does not change the RustQEC {{ docs_version.release_line }} documentation line. Read the support and migration contract and evidence guide before applying results to another circuit.
