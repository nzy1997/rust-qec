Atom loss

From atom loss to logical predictions

Follow one experiment from a noisy Mid-SWAP circuit to loss-visible samples, envelope decoding, and a check against the known answers.

{% endblock hero %} {% block main %}

Keep the loss information through the experiment

An atom can disappear before it is measured. The remaining record must describe both whether the atom was lost and the measured value when it survived. Treating a lost value as an ordinary 0 or 1 can create misleading detector parities.

RustQEC carries loss flags alongside measurement values and exposes them to its loss-aware decoders. This tutorial uses a distance-3, two-round Mid-SWAP Z-memory circuit: the same circuit and sampled dataset continue through every step below.

You need rustqec on PATH and Python 3 for the final result check. The default CLI includes envelope matching; this example does not require the optional ILP solver. Run the commands in order in a fresh working directory.

Install the CLI
cargo install --locked rustqec-cli --version 0.3.0

Without Rust, use the native installer.

1. Construct a circuit with atom loss

Set Pauli noise and atom-loss probabilities separately. The Mid-SWAP generator produces loss-visible measurements, whose records contain interleaved loss_flag,value_bit pairs.

rustqec circuit gen \
  --code surface_code --task rotated_memory_z_midswap \
  --distance 3 --rounds 2 --noise 0.002 \
  --operation-loss-probability 0.002 \
  --measurement-loss-probability 0.003 \
  --out circuit.stim

Output: circuit.stim, including the loss-visible measurements and the logical observable that will be predicted.

2. Sample public inputs and private answers

Export 64 shots in measurements_blinded mode. This preserves the measurement records, including loss flags, while keeping the answer key separate. The logical-X support 1,8,15 belongs to this specific generated circuit; it must be recomputed for a different layout.

mkdir -p data
rustqec dataset export \
  --circuit circuit.stim --shots 64 --seed 7 \
  --mode measurements_blinded --logical-x-qubits 1,8,15 \
  --public-out data/public --private-out data/private
BundleContentsUsed by
data/public/Circuit, manifest, and packed measurement rows in shots.b8The decoder
data/private/Manifest, physical logical-error targets in answers.b8, and hidden logical-input bits in masks.b8The experiment owner when scoring

The two manifests share a dataset_id. Keep the private bundle out of decoder inputs. Under a set loss flag, the accompanying value bit is a placeholder; changing that placeholder must not change the decoder's prediction.

3. Decode the sampled records

Pass only the public bundle to envelope matching. The decoder uses the circuit and loss-visible rows to predict logical outcomes; it does not read the private answers or masks.

rustqec decode --decoder envelope-matching \
  --dataset data/public \
  --out predictions.b8 --stats-out decode-stats.json

Outputs: predictions.b8 contains one logical prediction per shot. decode-stats.json records decoded shots, distinct loss patterns, compilation and decoding time, and failures. For this one-observable example, each packed prediction occupies one byte.

Matching or exact MLE?

Envelope matching is included in the default CLI. Exact envelope-mle is available with the ilp feature or the official native archive. It solves a different optimization problem and can take longer. Each decoder has circuit acceptance limits; enabling a solver does not make every loss circuit supported.

4. Check the logical predictions

As the experiment owner, compare predictions with the private physical logical-error targets. The hidden logical-input masks are already accounted for in those targets; do not apply them a second time.

python3 - <<'PY'
import json
from pathlib import Path

public = json.loads(Path('data/public/manifest.json').read_text())
private = json.loads(Path('data/private/manifest.json').read_text())
stats = json.loads(Path('decode-stats.json').read_text())
predictions = Path('predictions.b8').read_bytes()
answers = Path('data/private/answers.b8').read_bytes()
assert public['dataset_id'] == private['dataset_id'], 'Mismatched datasets'
assert public['circuit']['observables'] == 1, 'This check expects one observable'
assert len(predictions) == len(answers) == public['shots'] == stats['shot_count'], 'Incomplete rows'
assert all(bit in (0, 1) for bit in predictions + answers), 'Invalid padding bits'
errors = sum(predicted != answer for predicted, answer in zip(predictions, answers))
print(f"Decoded shots: {stats['shot_count']}")
print(f"Loss patterns: {stats['distinct_loss_patterns']}")
print(f"Logical errors: {errors} / {public['shots']}")
PY

Checked output for the commands above:

Decoded shots: 64
Loss patterns: 10
Logical errors: 0 / 64

This small seeded example checks that the workflow is connected, including multiple loss patterns. Zero failures in 64 shots is not evidence of a zero logical error rate. Estimating performance requires larger experiments, uncertainty estimates, and stated circuit and noise conditions.

Supported circuits and next experiments

Envelope decoding is beta. This walkthrough demonstrates one generated Mid-SWAP case. It does not establish support for arbitrary circuits, loss rates, or circuit sizes. The compiler can reject inputs outside its acceptance rules with unsupported_circuit; a rejection is not a logical prediction.

When changing the circuit, update its logical-X support and regenerate both bundles together. Keep any failed or incomplete decoding run separate from a successful logical-error-rate result.

The repository also includes a pinned d=5, r=15 Mid-SWAP MLE control and an excluded conventional circuit that must fail before producing prediction or statistics files. See the support contract and regression commands for these separate controls.
